# 2026-10-08 内存与额度保留验收

## 原因与修复

旧版 0.1.4 连续运行约 9 天，`sample` 记录实际内存占用 2.1 GB、历史峰值 29.2 GB；进程 CPU 约 921%。调用栈反复停留在 `JSONRPCClient.connect()` 的 EOF 读取回调与 `swift_task_create_commonImpl`。EOF 后没有取消读取回调，关闭连接也没有关闭管道句柄，导致反复创建任务和大量内存分配。app-server 子进程本身只有几十 MB。

0.1.5 在 EOF 时立即取消读取回调，连接关闭时释放全部管道，以连接代次隔离旧回调；stderr 写入空设备，避免未读取的管道填满并阻塞刷新。残缺消息缓冲上限为 1 MiB，停止显示时移除状态项。

## 额度策略

暂时失败、超时、CLI 暂不可用、空响应、长时间未更新或跨过重置时间都保留上次成功值，不推算新百分比。菜单与提示显示缓存状态，更新时间保持原成功时间。成功值和账户指纹持久化，重启后先恢复缓存并核对账户。确认登出、账户变化或 API key 账户时清空旧额度；真实 0% 正常显示。

## 验收证据

- `Scripts/check-refresh.sh` 通过：100 次 EOF/重连，未累积管道句柄；超时和超长残缺消息均释放连接；256 KiB stderr 不阻塞请求。
- 同一脚本直接验证 AppState：失败、空响应、一天未更新与重启均保留 84%；账户切换、登出和 API key 清空；服务端返回 0% 时更新为 0%。使用本地假服务，不访问真实账户。
- Release 构建、应用签名与 Info.plist 校验通过；已部署的二进制 SHA-256 与构建包一致，版本为 0.1.5（6）。
- 部署后采样：实际内存 20.0 MB、峰值 27.5 MB，CPU 0%；仅有一个 app-server 子进程和 3 个管道句柄。真实额度读取成功，缓存包含 5 小时与周窗口及账户指纹。
- 主动终止本应用拥有的 app-server 后，管道句柄随即释放；随后自动启动新的子进程，于北京时间 10:10:25 再次读取成功。重连后 CPU 仍为 0%，管道句柄保持 3 个，RSS 未上涨。

此处为针对故障路径和短期运行的验收；尚未重复旧进程的 9 天运行时长。机器缺少 XCTest，采用可独立编译运行的回归脚本。原生 UI 读取工具两次超时，菜单文字由 AppState 与菜单构建代码核对，未取得 UI 截图证据。
